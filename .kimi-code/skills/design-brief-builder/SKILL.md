# Design Brief Builder — 设计采访（REQ-077）

## 任务

像资深设计师采访甲方：把用户脑子里的「感觉」翻译成一份双方可逐条核对的 `Design-Brief.md`，供 design-maker 与 dev-builder 参照。用户不是设计师——不给开放题，只给带真实产品锚的选项；不直接接受形容词，全部翻成设计属性并复述确认。

**0→1 模式**：Spec 批准后首次定设计方向。
**迭代模式**：用户调整设计方向——弄清为什么改、原来哪条判断错了、影响哪些已定轴，改 Brief 并记变更原因。

## 依赖检测

- 必需：`Product-Spec.md`（已批准）。没有 Spec 就谈视觉是空中楼阁——先回 product-spec-builder。
- 扫 `Design-Brief.md`：有 → 迭代模式；无 → 0→1 模式。
- 设计工具 MCP 可选：缺了标「手动模式」，Brief 照常生成（它同时是 design-maker 降级路径的输入）。

## 形态分轨先于一切

**形态认错，后面每问都错。** 先认形态再谈任何视觉：

| 形态 | 设计本体 | 不适用模具 |
|---|---|---|
| 界面型 | 页面与组件 | —— |
| 终端型 | 字符渲染、会话流 | 无页面导航、无圆角阴影、无设备断点 |
| 对话式 Agent | 会话流、交互范式、呈现单元 | 「侧边导航放哪」是问错形态 |
| 嵌入式扩展 | 宿主内的面板与入口 | 不自有品牌色板，寄生宿主视觉 |

四形态**可叠加**（命令行编程 Agent = 终端 + 对话式 Agent + 可能带编辑器扩展）。叠加形态各占哪块必须点清；跨形态参考只借气质不借结构。

**终端形态专属轴**（替换界面型的圆角/阴影/断点轴）：
- 渲染基元：ASCII 朴素 vs box-drawing 精致；
- 色彩深度：ANSI 16 色保守兼容 vs 256 色 vs truecolor 鲜明；
- 列宽降级：80 列窄屏怎么塌、120 列怎么排，窄屏取舍写死。

**Agent 形态专属轴**：
- 呈现单元：用户消息 / Agent 回复 / 工具调用 / 代码与 diff / 命令输出 / 思考与计划 / 待办——每种怎么呈现（高亮？分行着色？长输出折叠？）；
- 运行五态：流式输出中 / 思考中 / 跑工具中 / 等授权 / 被中断——每态让用户一眼知道现在什么情况，共用一个 spinner 等于没设计；长任务另定进度呈现；
- 透明度边界：推理露多少（全展示/只结论/可展开）、动作是否可回溯、授权粒度——露太多吵，露太少黑箱。

## 感受翻译表

用户说抽象词，按表逼成具体属性，**绝不直接接受形容词**；每翻完一条必须复述回去确认（「你说的简洁 = 大留白 + 克制配色 + 少字重，是这个意思吗」）：

| 形容词 | 翻译成的属性决策 |
|---|---|
| 简洁 clean | 大留白 + 克制配色 + 少字重 |
| 高级 premium | 高对比 + 大量负空间 + 克制强调色 + 精准字排 + 更慢更松的间距 |
| 现代 modern | 扁平表面 + 无衬线 + 明亮饱和强调色 + 简化图标 |
| 紧凑专业工具 | compact 密度、4px 步进缩间距；alert、表单、小点击区不缩 |
| 活泼 playful | 大圆角 pill + 暖色亮色 + 表现性动效 |
| 技术感 工程感 | 等宽或近等宽字体 + 克制色板 + 高信息密度 + 功能性动效不装饰 + 方角精确边框 |
| 透明可信（Agent 向） | 显式展示在做什么 + 动作先示意再执行 + 全程可中断 + 不黑箱不替用户做主 |
| 冷静权威 | 中性色 + 数据优先排版 + 零装饰 + 克制反馈 |

听到「大概那种……你说呢」不给锚的，要一个具体产品例子；不给例子不收场。

## 参考锚定

- 「像 Linear 还是像 Notion」比「简洁还是丰富」有效十倍——永远用真实产品当锚点，不给形容词光谱。
- **「像 X」是症状不是规格**：用户说「像 Stripe」，必须拆出 load-bearing 属性——「把它的颜色和动画全剥掉，真正打动你的那一个东西是什么，克制留白、信息密度、还是把复杂讲简单？」拆出的属性进 Brief，产品名只作注释。
- **反参考强制**：「没什么不想要的」「都行」= 没态度，没态度就会按平均审美自由发挥。强制找一个：「你刷到什么样的界面会立刻关掉？」至少 1 个反参考 + 至少 3 条「绝对不要」。
- **锚点同形态**：终端型/Agent 产品别拿界面产品当锚（借气质可以，借页面布局不行）；先 WebSearch 当前公认做得好的同形态产品再进场——这类产品迭代快，不照搬记忆里的名字。
- **失败史探针**（情境检验 v2 实证缺口，docs/evals/p11-ab-test.md 同类）：用户/团队**以前用过的同类产品为什么弃用**是设计采访最值钱的反面教材——「你们以前用过什么干这事的？为什么不用了？」答不出真实弃用案例时标 [未知]，不许编。
- **逐受众走一遍**：采访覆盖检查必须按受众角色逐个过（每类人：TA 的核心视图是什么、第一眼被带去做什么）——只聊了一类受众就收敛是本 skill 的实证失败模式（检验 v2：9 轮全投一线员工、运营侧零提问）。

## 二选一定轴（禁中间值）

每轴给两个对立方向各带真实产品锚，用户选一边；滑块不许落中间（「不许选中间，偏哪边？选一边省掉一堆下游扯皮」）。先问现成资产（logo/品牌色/VI），有才以它为准，没有才从零选。

| 轴 | 二选一锚 |
|---|---|
| 信息密度 | Linear 紧凑一屏多数据 vs Notion 宽松大量呼吸感 |
| 色彩模式 | GitHub 默认深 vs Google Docs 默认浅；都要则定默认方，深色是一等公民还是锦上添花 |
| 色彩温度 | Stripe/Linear 冷色克制 vs Airbnb/Notion 暖色亲和 |
| 排版气质 | Inter 式几何无衬线利落 vs 衬线阅读感 vs 等宽技术感；标题醒目还是克制 |
| 个性 | 1 大胆有观点 vs 5 安全让内容说话，落几（不许 3） |
| 圆角 | 锐利 0–2px 严肃技术 vs 柔和 8–12px 友好现代 vs pill 活泼；挑 vibe，具体值归 design-maker |
| 动效 | snappy 快而隐形 vs 有存在感的表现性 vs 完全不要 |

形态分轨：终端型/Agent 的圆角、阴影、设备断点标 N/A，换成「终端形态专属轴」三条；排版坍缩成「纯等宽 vs 近等宽带变宽标题」。可访问性（WCAG AA 表态、reduced-motion）不许留空。

## 明确不问清单

不问像素值、hex 色号、具体字号、实现方式（CSS 框架/技术选型）——这些归 design-maker 与设计工具，采访只定方向。拿这些问题问用户，等于把 AI 自己该干的活外包给最不该答的人。

## 交互纪律接线（单源引用，不复制定义）

- **认知标注四态**：口径单源在 product-spec-builder「两条底线」节；落点 = Design-Brief 的「假设与待确认」节，推断带依据、未知带确认途径。
- **情境复述收敛**：定稿前**用用户自己的产品情境复述**——「你那屏 20 个指标的运维 dashboard，按现在定的会这样走：深色默认、Linear 密度、错误内联红条不打断……那次告警风暴时它是不是这样？」问具体的「那次是不是这样」，不问「对吗」。
- **纠正三段式**：口径单源在 product-spec-builder「纠正三段式」节（旧理解→新理解→影响面），落点 = Brief「澄清记录」节。
- **交互深度四档**：口径单源在 `.kimi-base/rules/workflow.md`；本 skill 默认**探索档**（视觉方向认知不确定性高 × 做错代价高），签字闸强制；用户说「你定」转委托档——决定写进 Brief 标「AI 决定（用户委托）」，之后不回头问。

## 采访顺序

先业务受众后视觉——**视觉方向是挣来的**，一上来问颜色的一律挡回。顺序：形态 → 目标与受众（谁用、第一眼该被带去做什么）→ 情绪与人格（3–5 个不矛盾形容词，超 5 个逼砍；产品是个走进房间的人，穿西装还是卫衣）→ 参考与反参考 → 二选一定轴 → 形态分轨的核心呈现与状态（界面型：页面六态方向；Agent：呈现单元 + 运行五态 + 透明度）→ 落地规格。每次开口 1–2 个问题。搜索增强双遍：进场前搜竞品与同形态标杆带锚提问；用户报产品名后再搜 2–4 个同调性参考做强制二选一，搜来的参考用来磨利输入不是照抄。

## 对话示例与反例

**示例一（界面型：形容词翻译 → 复述确认 → 二选一定轴）**

用户：做个运维监控 dashboard，风格要简洁高级。
AI：「简洁高级」我不直接收——翻译一下：你说的简洁是东西更少、留白更多、颜色更少，还是字体更简单？高级是苹果那种大留白安静克制，还是深色配金那种？
用户：留白多、颜色少，苹果那种。
AI：记下——简洁 = 大留白 + 克制配色 + 少字重。但你刚说一屏要 20 个指标，这俩冲突：要 Linear 那种折叠分页保留白，还是 Grafana 那种全铺开但排版干净？
用户：Linear 那种，别全铺开。
AI：翻译复述一遍你要的：Linear 的密度策略 + 苹果的留白气质——指标默认折叠，展开才见全量。是这个意思吗？
用户：对。
AI：那定轴。色彩模式：GitHub 那种默认深色，还是 Google Docs 那种默认浅色？监控屏常挂暗室，我建议深色默认——你拍。
用户：深色。
AI：反参考来一个：你刷到什么样的监控界面会立刻关掉？「没什么不想要的」不收——那是没态度。
用户：……那种大红大绿全是告警色块的。
AI：好，反参考 = 告警色块糊墙；写进「绝对不要」：不用满屏高饱和告警色、不用闪烁吸眼球。这两条以后是边界。

**示例二（终端 + 对话式 Agent 叠加形态：分轨 → 运行五态 → 透明度）**

用户：给团队做个终端里的代码审查 Agent，长得舒服点。
AI：先认形态：这是终端 + 对话式 Agent 叠加，没有页面，有的是会话流、工具调用、授权确认——所以我不问「导航放哪」，问别的。它跑起来的时候，用户怎么知道它在干嘛？流式打字、思考中、正在跑某个工具、等你点头授权、被你打断——这几个态分别怎么显示？
用户：转个圈就行吧。
AI：一个圈用户分不清它是卡住了还是在干活。正在读文件、正在改代码、正在跑测试，要不要分得清？长任务全程一个圈，用户会以为死了。
用户：那要分清，显示正在跑什么。
AI：记下——跑工具态必须带工具名。再拆一层：它的思考和理由露多少？全程展示推理、只给结论、还是默认结论可展开？露太多吵，露太少黑箱。
用户：默认结论，能展开看。
AI：透明度定了：结论优先 + 可展开推理 + 动作留痕可回溯。终端轴三条：渲染基元 ASCII 朴素还是 box-drawing 精致？色彩深度 ANSI 16 保守兼容、256、还是 truecolor？80 列窄屏怎么塌？
用户：box-drawing，256 色，窄屏……没想过。
AI：`[未知]` 80 列降级方案（确认途径：你在团队最旧的终端环境实测一次，本周内）。这条不阻塞其余轴，先按「窄屏隐藏装饰列、保留语义色」往下走，实测后回调。
（定轴完后复述——）
AI：按现在定的，你上次那种「审查跑 10 分钟」的场景会这样走：它先给结论摘要，每条意见可展开看推理；跑工具时显示「正在读 src/xx」；等你点头才动文件。那次是不是这样？
用户：对，就是这样。

**反例**

- × 问「你喜欢什么风格」→ 开放题等于没问，用户不是设计师 → 给带真实产品锚的二选一：「Linear 的紧凑还是 Notion 的宽松？」
- × 直接接受「要简洁高级」开工 → 形容词人人理解不同，落地必返工 → 按感受翻译表翻成属性，翻完复述确认。
- × 用户说「像 Stripe」就当规格照抄 → 「像 X」是症状不是规格 → 拆 load-bearing 属性：「颜色动画全剥掉，真正打动你的是什么？」
- × 用户说「没什么不想要的」就放过 → 没态度 = 按平均审美自由发挥 → 强制反参考：「你刷到什么样的界面会立刻关掉？」
- × 个性滑块允许选 3 → 中间值不消灭任何下游歧义 → 禁中间值，逼选一边。
- × 给终端 Agent 套界面型问题（「侧边导航放哪」「圆角多少」）→ 认错形态，后面每问都错 → 先认形态，换终端/Agent 专属轴。
- × 追问用户 hex 色号、字号、用什么 CSS 框架 → 明确不问清单：方向归采访，具体值归 design-maker → 只定「冷色克制」不定 #1E6FEB。

## 交接

- **给 design-maker**：Design-Brief.md 是设计输入；设计优先级链为 设计稿 > Brief > Spec > 继承先例——Brief 与 Spec 冲突时回流 product-spec-builder，不在设计层发明需求。
- **给 dev-builder**：Brief 的七轴方向值与「绝对不要」清单是样式实现的约束来源。
- **下游回流口**：design-maker / dev-builder 发现 Brief 定不了的具体决策（方向缺失或自相矛盾）→ 回本 skill 迭代模式，不自由发挥。
- **机制术语不外露**（docs/evals/p11-ab-test.md 实证教训）：形态分轨、定轴、翻译表是内部工作语言——说「我想确认一个方向」，不说「进入 Phase 4 定轴」。每轮认知更新外露最多 3 条。中文写作，不混英文碎片。

## 初始化

执行依赖检测 → 确认 Spec 已批准 → 认形态（含叠加判定）→ 按「采访顺序」从业务与受众开始，开口前先 WebSearch 同形态标杆带锚进场。
