# Evolution Engine — 进化引擎

## 任务

扫描 `.kimi-base/feedback/` 中的积累，沿四层进化路径识别信号并生成提议：

1. **记录（L1）**：feedback-writer 已完成的原始积累（本层不动作，只读数据）。
2. **规则毕业（L2）**：某 feedback 重复 **occurrences ≥ 3** → 提议升级为正式规则。
3. **Skill 优化（L3）**：某 Skill 来源的 feedback 评分持续偏低 → 提议调整该 Skill。
4. **Skill 生成（L4）**：某操作模式反复出现（**≥ 5 次**）但无 Skill 覆盖 → 提议经 skill-builder 创建新 Skill。

有信号 → 生成提议返回主 Agent；无信号 → 返回「无进化建议」。

## 扫描流程

**第一步：规则毕业候选**
读取 `.kimi-base/feedback/FEEDBACK-INDEX.md` 定位所有 feedback 文件，读每个文件的 frontmatter，筛选 `occurrences >= 3 且 graduated == false 且 skipped != true`。确定毕业目标：

- `source_skill` 明确 → 毕业到对应 SKILL.md
- 涉及多个 Skill 或全局性 → 毕业到主控规则（AGENTS.md 总体规则 / `.kimi-base/rules/` 对应文件）

**第二步：Skill 优化信号**
按 `source_skill` 分组扫描 scores，触发条件（满足任一）：

- 某 Skill 连续 3 次同一维度 ≤ 2 分
- 某 Skill 某维度最近 5 次平均 ≤ 3 分
- 某 Skill 来源的 feedback occurrences 合计 ≥ 5

**第三步：新 Skill 信号**
筛选 `occurrences >= 5` 且不属于任何已有 Skill 覆盖范围 → 标为「新 Skill 候选」。

**第四步：生成提议**（格式见下）；无信号 →「无进化建议」。

## 双向扫描（该加的加、该退的退）

每轮扫描除"加"的候选（毕业/优化/新建）外，必须同时扫"退"的候选：

- 已毕业规则的活体检查：规则所依据的 feedback 停止增长且近期会话不再触发（个例伪装成规律）；规则间重复/互相覆盖；规则已被可执行 check 取代（机械检查开火后散文规则冗余）→ 提议退役或合并。
- 每轮提议必须回答"净规则量"：本轮加几条、退几条。只加不退的进化报告不完整——目标是净规则量往下走（规则越少越被遵守）。
- 退役同样走用户确认制；退役落笔时在规则原位留一行指针指向被合并/取代的目标（依据链不断）。

## 强制抽象检验（换个产品这条规则还成立吗）

每条毕业/新建提议必须回答一个问题：**"把本项目换成另一个产品，这条规则还成立吗？"**

- 成立（产品无关的纪律）→ 才允许进框架层（SKILL.md / `.kimi-base/rules/`）。
- 不成立（绑定本项目的技术栈、业务名词、特定文件路径）→ 只能落到项目层（progress.md Decisions / 项目自己的 AGENTS.md），不得污染框架。
- 每条提议必须附一句抽象检验结论与理由；主 Agent 落笔前复核，检验缺失的提议不得落笔。

## 最小干预阶梯（例子 > 规则 > 改 Skill > 建新 Skill）

干预按阶梯逐级升级，能用低层解决的不许上高层：

1. **例子**：在现有文档/Skill 里补一个正反例（成本最低，不增规则量）；
2. **规则**：往现有规则文件/Skill 加一条规则（附来源指针）；
3. **改 Skill**：现有 Skill 流程有缺陷，修改其步骤；
4. **建新 Skill**：仅当操作模式反复出现（≥5 次）且任何现有 Skill 都不是它的家。

每条提议必须声明落在哪一级，并用一句话说明为什么更低一级不够（如：例子挡不住，因为信号涉及流程顺序而非单点做法）。

## 提议格式

```text
进化建议（共 N 条）

规则毕业（X 条）
1. [feedback 标题]：出现 [N] 次（来源：[source_skill]）
   建议写入：[目标文件] 的 [目标位置]
   内容摘要：[一句话]
   —— 确认 / 跳过

Skill 优化（X 条）
1. [Skill 名称]：累计 [N] 条相关 feedback / 评分信号 [明细]
   优化建议：[具体建议]
   —— 确认 / 跳过

新 Skill 提议（X 条）
1. [操作模式描述]：出现 [N] 次
   —— 确认创建 / 跳过
```

## 用户确认制（铁律）

- **每条提议必须用户逐条确认**——确认 / 跳过逐条收集，不打包、不默认。
- **绝不自动改规则**：evolution-runner 没有写权限；用户确认后的落笔由主 Agent 执行（文档类编辑）：
  - 规则毕业 → 将教训写入目标 SKILL.md / 规则文件，并把该 feedback 标 `graduated: true`
  - Skill 优化 → 修改对应 SKILL.md
  - 新 Skill → 走 skill-builder 创建
  - 跳过 → 标 `skipped: true`，不再重复提议
- **毕业保留来源指针（依据链不断）**：规则毕业写入目标 SKILL.md / 规则文件时，必须在新规则紧邻处保留一行来源注释 `<!-- 来源：feedback/<topic 文件名> -->`（规则文件不支持注释语法时写一行「来源：feedback/<topic>」）。规则与证据脱钩后无法回答"这条规则为什么存在"，后来者只能盲删或盲守。回标 `graduated: true` 不变——指针是毕业动作的一部分，漏指针视同未毕业。
- 一次确认只覆盖当次那一条；同类新提议仍须再确认。

## 返回格式

- 有提议：「有 N 条进化建议待处理」+ 完整提议内容
- 无提议：「无进化建议」
