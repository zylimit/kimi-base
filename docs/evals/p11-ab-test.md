## 4. 总判

**新版是真实的理解质量改进，不是变长。** 长度增长（31.9KB vs 21.1KB）由三个机制性差异贡献且各自带来指标收益：(1) 首轮索取触发事件 → 事实 2（牛奶案）从 0 到命中，这是全部指标中权重最高的一条；(2) 四态认知标注 → 认知标注指标从无到有，且 0 处推断冒充事实；(3) 复述收敛 → 给了用户纠正入口并得到确认。旧版遗漏牛奶案的后果是实质性的：其 spec 的成功标准（SC-002"零扯皮"）靠用户临场发挥，而新版 spec 的每条核心 REQ（003 单号/004 照片/006 实时提醒）都直接锚定在 8000 元事故的根因链上。

公平性备注：两组用户扮演为同脚本不同 LLM 实例，旧版组用户在第 2 轮和签批时主动多倒了信息（生鲜规则、WMS 史），即使如此旧版仍漏 2 条核心事实——结论方向稳健。

## 5. 发现的新版 skill 新问题

1. **内部机制术语泄漏到用户侧对话**：新版访谈者对真实用户说"判档：探索档"（N29）、"路由表命中「手工传递+重复录入」"（N53）、"进四线采集"（N55）、"押后策略"（N178）、"委托档"（N184）等引擎内部词汇。仓库主管人设的用户不会懂"路由表/四线/押后"，真实场景会造成困惑。建议 skill 增加一条：认知更新可展示，但内部机制名（档位/路由表/四线）不对用户外露。
2. **每轮认知更新列表偏长**：单轮访谈者输出最长 3.6KB（run log），对真实用户阅读负担重；可考虑折叠为"本轮新确认 N 条 + 变更项"，全量清单只进产物。
3. 轻微：新版 spec 混入英文碎片（N135"partly 是因为"），工艺问题。
