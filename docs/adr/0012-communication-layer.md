# ADR-0012：沟通桥梁层（软层）重构——认知标注、业务含义过链、交互深度四档

状态：Accepted · 日期：2026-09-08 · 决策者：用户 + 主 Agent
Enforced-by: unit, manual:spec lint 认知标注检查与派单契约测试机械执法；追问质量与复述收敛属提示词纪律（有实证依据的例外：knowing-but-not-showing 证明标注必须模板强制）

## 背景

v3.0 P0-P4 把工程面（证据/评审/强度档化）推进到姐妹仓前列，但用户指出产品本质问题：框架是人和 AI 共同理解问题、形成判断、完成交付的沟通桥梁，业务理解与工程执行必须同样强大。软层审计（16 skills/8 agents/13 模板逐行）发现七大断点：认知无标注、业务含义不过链、交互深度一刀切、迭代不采动机、界面阶段缺失、记忆无依据链、无反例回流。外部实证（knowing-but-not-showing 95% 不澄清、Lost-in-Conversation 39% 退化、ReqElicitGym 隐性需求召回 <50%）证明这些不能靠模型自觉。完整取证与设计见 docs/COMMUNICATION-LAYER.md。

## 决策

1. **认知标注四态进 Spec**：Spec 设"现状与假设"节，条款强制标 `[确认]`（用户确认+来源）/`[推断]`（AI 推断+依据）/`[建议]`（AI 提议+理由）/`[未知]`（未知+确认途径）；未标按推断论处；spec lint 校验标签形态（推断无依据/未知无确认途径 → error）。`[待补充]` 旧标记并入 `[未知]`。
2. **业务含义过链**：REQ 条目增动机/受益人字段（planned 面）；派单包六字段扩为七字段（+业务上下文，主 Agent 从 Spec 抄，fresh 实例不许猜）；code-review/bug-fixer/test-builder 增"需求存疑"回流通道（回流 psb 迭代模式，反例进 Spec"规则与例外"节）。
3. **交互深度四档**：直推/确认/探索/委托，判据=认知不确定性×做错代价（与既有审批三档正交——审批管操作风险，交互档管认知风险）；澄清记录持久化于 Spec"澄清记录"节，问过的不再问；签字闸对直推档豁免。
4. **psb 方法层重写**：向人学业务四线（as-is 真实故事/受益受损者/规则与例外/决策历史）、问"上一次"句式、答案解析器（弱化词→标推断要例子、"都要"→逼取舍、矛盾→并排摆出）、答案→下一步路由表、情境复述收敛（用用户的案例讲"那次会怎么走"）、收敛=待定清零+复述通过（维度清单降级为覆盖检查器）。
5. **记忆依据链**：progress.md Decisions 强制理由+被否方案+适用范围；supersede 显式链；evolution 毕业保留来源 feedback 指针；用户纠正产出"旧理解→新理解→影响面"三段式变更记录。
6. **阶段专业化与工艺**：arch 补业务推导线（数据归属/一致性/故障后果/团队能力）；dfx 补定标追问（业务损失→可接受边界→目标值）；界面阶段最低要求=真实任务走查；对话型 skill 补多轮对话示例与反例；执行型 skill 补反合理化清单；重复块（回执信封/交接声明/路由表）下沉单源。
7. **访谈-冻结-干净执行**：spec 批准即冻结成文，下游工作在干净上下文从 spec 恢复（39% 退化区对策）；对话补丁禁止（纠正必须落成 spec/工件变更）。

## 备选与拒绝理由

- 全面加厚所有 skill 到 cc 级篇幅 → 拒绝：cc dev-builder 499 行中项目特定沉淀不值照搬；细节按需加载（references/），宪法与清单保持短（ETH 实证：长指令文件降低成功率）。
- 引擎强制每轮对话标注（机械扫描对话）→ 拒绝：对话不是机器可判面；机械执法边界=产物（spec/派单包/记忆），过程纪律归 skill。
- 引入 BMAD 式角色剧场 → 拒绝：无对照证据，纯流程 cosplay。

## 后果

- Spec 从"需求清单"升级为"理解契约"（含认知状态与依据链）；dev-planner 的关键未知排序有原材料。
- 直推档存在后，小改动的确认仪式成本消除；签字闸保留给真重要的决策。
- 软层改进的验收同样走证据法：P11 收尾用真实情境前后对比检验（理解准确度/返工轮次/重复表达次数）。
